# 맛소금 블로그 이전

`https://blog.msalt.net`을 Tistory에서 Astro 정적 사이트로 이전하는 프로젝트입니다. 게시글의 원문과 기존 URL을 보존하고, 글과 이미지가 Tistory 서비스에 의존하지 않도록 합니다.

## 목표

- 글 주소와 카테고리 주소를 현재와 최대한 동일하게 유지합니다.
- 원본 HTML, 메타데이터, 이미지와 첨부 자료를 Markdown 변환 전에 보관합니다.
- 현재 사이트의 디자인과 정보 구조를 Astro로 재현합니다.
- RSS, canonical URL, sitemap, robots.txt 등 검색과 구독 기능을 유지합니다.
- 이전 및 새 사이트 검증이 끝날 때까지 Tistory 원본과 DNS 설정을 유지합니다.

## 기술 구성

- Astro 정적 사이트
- Markdown 게시글과 frontmatter
- GitHub 저장소: `msaltnet/blog-msalt-net`
- 호스팅: GitHub Pages를 사용하며, 정적 빌드 산출물은 저장소 루트의 `docs/`에 생성합니다. 저장소 Settings → Pages에서 배포 소스로 `Deploy from a branch`, 브랜치의 `/docs` 폴더를 선택합니다. 기본 빌드는 프로젝트 페이지 경로 `/blog-msalt-net/`을 사용합니다.

## 로컬 개발

Node.js 22.12 이상과 npm이 필요합니다.

```powershell
npm install
npm run dev
```

정적 사이트를 `docs/`에 출력하려면 `npm run build`를 실행합니다. 빌드할 때 `docs/`의 기존 파일은 모두 정적 산출물로 교체되므로 소스 문서는 `migration/`에 둡니다. `blog.msalt.net` 커스텀 도메인 연결 후 루트 경로로 배포할 때는 PowerShell에서 `$env:SITE_BASE='/'`를 설정한 뒤 빌드합니다. 개발 서버는 기본적으로 루트 경로를 사용합니다. 글 목록·이미지의 출처와 변환 보고서는 아래 명령으로 점검합니다.

```powershell
python scripts/verify.py
```

## 이전 순서

1. 공개 사이트의 게시글, 카테고리, 태그 및 URL 인벤토리를 수집합니다.
2. 원본 HTML, 이미지, 댓글 등 복구에 필요한 자료를 백업합니다.
3. 인벤토리를 기준으로 Astro 프로젝트와 현재 디자인을 구성합니다.
4. 게시글을 Markdown으로 변환하고 이미지와 첨부파일을 로컬화합니다.
5. 게시글·카테고리 URL, RSS, SEO 메타데이터 및 sitemap을 구현합니다.
6. 자동 검증과 브라우저 표본 검토를 마친 뒤 미리보기 환경에서 확인합니다.
7. 최종 동기화와 검증 후에만 호스팅 및 DNS 전환을 진행합니다.

Markdown 변환 과정에서 표 등 복잡한 본문은 HTML로 보존할 수 있습니다. 우선 기준은 Markdown 순도보다 원문 손실 방지입니다.

## 데이터 디렉터리

```text
backup/
  html/       # 게시물 원본 HTML
  images/     # 게시물별 원본 이미지
  metadata/   # 게시글, URL, 카테고리, 태그 인벤토리
src/content/posts/
  *.md        # 변환한 게시글
public/images/posts/
  <post-id>/  # 로컬 게시물 이미지
scripts/
  inventory.py
  migrate.py
  verify.py
```

백업은 Markdown 변환 결과와 별도로 보존합니다. 백업 HTML에는 Tistory가 발급한 만료형 미디어 URL이 들어 있어 `backup/`과 `migration/images.csv`는 Git에서 제외합니다. 비밀 값, 인증 정보, 브라우저 쿠키는 저장소에 기록하지 않습니다.

## 현재 확인한 출발점

- 공개 홈페이지는 `https://blog.msalt.net/`입니다.
- 2026-09-26 인벤토리에서 공개 글 320건, 카테고리 11개를 확인했습니다. 홈페이지는 전체 글 수 321개를 표시하고 카테고리 표시 수 합계도 321이지만, 실제 목록에서 한 건을 찾지 못했습니다. 조회한 320건은 모두 접근에 성공했습니다.
- `/355`처럼 게시물 번호가 연속적이지 않으므로 번호를 추정하지 않고 실제 URL을 수집합니다.
- 현재 공개된 게시물 URL 예시는 `/360`이며, 첨부된 계획의 `/355`도 기존 URL 예시로 보존 대상에 포함합니다.
- 320건의 HTML 백업(약 13 MB)과 이미지 1,757개(약 613 MB)를 로컬 `backup/`에 저장했고 이번 수집에서 실패는 없었습니다. 공통 사이트 이미지도 게시물별로 반복되어 최종 사이트에는 본문 이미지만 옮깁니다.
- 새 사이트에는 댓글 기능을 두지 않으며, 기존 댓글 데이터도 이관 대상에서 제외했습니다. 게시물 원본 HTML과 이미지는 변환 검수용 로컬 백업으로 보존합니다.
- 320개 Markdown 파일과 본문 이미지 797개를 생성했습니다. 변환 과정과 확인 결과는 `migration/conversion-report.json` 및 `python scripts/verify.py` 출력으로 추적합니다.
- 11개 카테고리 경로와 태그 703개의 `/tag/...` 경로를 정적으로 생성합니다. 목록의 기존 `?page=N` 주소는 브라우저에서 20개씩 나누어 표시합니다. `/m/...` 모바일 주소는 같은 게시물의 기본 주소로 301 연결합니다.
- GitHub 저장소는 아직 커밋이 없는 빈 저장소입니다. 초기 콘텐츠가 준비되면 이 프로젝트 디렉터리를 해당 저장소의 서브모듈로 연결합니다.

## 배포 원칙

미리보기 및 전체 검증을 먼저 마칩니다. Tistory 원본을 즉시 삭제하지 않으며, DNS 변경은 이전 완료 단계에서 별도로 확인합니다. AdSense 등 수익화 설정은 사이트 이전과 SEO 확인 이후에 진행합니다.
